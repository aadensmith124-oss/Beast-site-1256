Build and integrate a fully functioning Telegram image-vouch reward system into my existing website. First inspect the entire existing Replit project, including the frontend, backend, authentication, Orders page, database, user accounts, and existing credit/balance system. Do NOT rebuild or replace anything that already works. Integrate this feature into the existing architecture.

The goal is: On the website’s Orders page, eligible orders should have a “📸 Submit Vouch” button. When the logged-in user clicks it, the backend must verify that the order belongs to that user and is eligible for a vouch, then generate a secure, cryptographically random, single-use, short-lived token associated with that specific user and order. The user should then be redirected to the Telegram bot using a Telegram deep link such as https://t.me/YOUR_BOT?start=TOKEN. Do NOT have users manually link their Telegram accounts.

The Telegram bot must validate the token with the website backend before accepting the vouch. If the token is invalid, expired, already used, or doesn’t exist, tell the user that the vouch link is invalid or expired and instruct them to return to their Orders page to generate a new one. Once validated, the bot should tell the user to submit their vouch as an IMAGE ONLY. Accept JPG, JPEG, PNG, and WEBP. Reject text, videos, GIFs, documents, audio, stickers, and other unsupported media. The actual vouch must be an image; do not use text as the vouch itself. The bot should clearly disclose that approved genuine vouches receive $0.50 in site credit and should not encourage fake, fabricated, exaggerated, or misleading feedback.

When the user sends an image, securely process it, preserve the Telegram file ID or securely store the image as appropriate, generate an image hash for duplicate detection, validate the token again, verify the associated order/user, consume the token so it cannot be reused, and create a PENDING vouch record. Send the submitted image to the private configured admin Telegram chat with the order number, internal user reference, reward amount ($0.50), submission time, and PENDING status. Include inline buttons for “✅ APPROVE” and “❌ REJECT”. Only Telegram IDs configured as admins may interact with these buttons.

When an admin approves a vouch, perform the entire operation atomically and server-side: verify the admin’s identity, verify the vouch is still PENDING, verify the order has not already received a vouch reward, verify the vouch has not already generated a credit transaction, mark the vouch APPROVED, add exactly $0.50 to the existing website user’s credit balance using the site’s current credit system, create an immutable credit transaction associated with the vouch and order, record the approving admin and timestamp, update the Telegram admin message to APPROVED, and notify the user through Telegram that their vouch was approved and $0.50 was added to their site credit balance. The reward amount must always be determined by the backend and must never be supplied by the Telegram user or frontend.

When an admin rejects a vouch, mark it REJECTED, do not award credit, record the admin, timestamp, and optional rejection reason, update the Telegram admin message, and notify the user that their vouch was not approved and no credit was added.

Add strong anti-abuse protection. A single order may only receive one approved vouch reward. A single vouch may only create one credit transaction. Prevent duplicate images from being rewarded using an image hash. Prevent expired or consumed tokens from being reused. Prevent users from submitting vouches for orders belonging to other accounts. Add reasonable rate limiting and database-level uniqueness/idempotency protections. Admin approval must be safe against double-clicks or replayed Telegram callbacks. Use atomic database transactions wherever appropriate.

On the website Orders page, add the “📸 Submit Vouch” button only to eligible orders. Eligibility must be checked by the backend, not trusted from frontend JavaScript. Clicking the button should optionally display a confirmation such as: “Submit a vouch for this order? Send an image showing your genuine experience through our Telegram bot. Approved vouches receive $0.50 in site credit.” Then generate the secure token and redirect the user to Telegram. Once an order has already received an approved vouch, disable/remove the button and show something like “✅ Vouch Submitted — $0.50 Credit Awarded.” If pending, show “⏳ Vouch Under Review.” If rejected, show “❌ Vouch Rejected.”

The website does NOT need a public vouch page, vouch gallery, public vouch API, or public image storage. Do not display submitted vouch images on the website. The only website integration is generating the Telegram submission link, tracking the vouch status for the user’s order, and updating the user’s existing credit balance after an approved vouch.

Use the existing database and architecture. If necessary, add a Vouches table/model containing fields such as id, order_id, user_id, telegram_user_id, telegram_username, telegram_file_id, image_hash, status, reward_amount, credit_transaction_id, created_at, reviewed_at, reviewed_by, and rejection_reason. Add a VouchTokens table/model containing id, token_hash, order_id, user_id, expires_at, used_at, and created_at. Store hashed tokens rather than raw tokens whenever practical. Add appropriate database indexes and unique constraints.

Create the necessary internal API endpoints for generating and validating tokens, submitting vouches, approving/rejecting vouches, and adding credit through the existing website credit system. For example, implement equivalent functionality to POST /api/vouches/create-token, GET /api/vouches/validate-token/:token, POST /api/vouches/submit, POST /api/vouches/:id/approve, POST /api/vouches/:id/reject, and a private server-to-server credit operation. Adapt the routes to the existing project’s API conventions instead of blindly creating duplicates. All sensitive API endpoints must be authenticated and authorized server-side.

The internal credit operation must only allow the backend to award exactly $0.50 for an approved vouch. Never allow the client or Telegram bot user to choose the amount. Make the credit transaction idempotent so the same vouch can never award multiple $0.50 transactions. Record the previous balance, new balance, user ID, vouch ID, order ID, transaction ID, timestamp, and approving admin when possible.

Use Replit Secrets/environment variables for BOT_TOKEN, ADMIN_CHAT_ID, ADMIN_USER_IDS, SITE_API_URL, and SITE_API_KEY. Never hard-code secrets or expose them to frontend JavaScript. Never expose Telegram user IDs or internal account information publicly. Validate all Telegram callbacks and API requests.

The bot should include basic commands such as /start, /help, /vouches, /stats, and /recent where appropriate. User-facing commands should work for normal users, while administrative commands and approval/rejection actions must be restricted to configured admin Telegram IDs. /stats should show useful totals such as total submissions, pending, approved, rejected, and total credit awarded.

Make the bot reliable in production: handle Telegram API errors, reconnect/recover when possible, safely handle duplicate Telegram updates, prevent duplicate processing, provide useful server-side logging without logging secrets, and include a /health or equivalent health-check endpoint. Make the implementation compatible with Replit’s deployment environment and existing project configuration.

Do not break existing login, registration, Orders, user accounts, credit balances, APIs, or other existing functionality. Reuse the existing authentication and credit infrastructure wherever possible instead of creating duplicate systems.

Finally, test the entire end-to-end flow: logged-in user opens Orders → clicks Submit Vouch → backend verifies ownership/eligibility → secure one-time Telegram token is generated → user is redirected to Telegram → bot validates token → user sends image → bot creates PENDING vouch → admin receives image → admin approves → backend verifies everything → exactly $0.50 is added to the correct existing website account → credit transaction is recorded → order becomes ineligible for another reward → Telegram user receives confirmation. Also test rejection, expired tokens, reused tokens, duplicate images, unauthorized admins, double approval attempts, and attempts to submit a vouch for another user’s order.
